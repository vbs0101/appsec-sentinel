# Security Policy

## Supported Versions

AppSec Sentinel is currently in active development.

Security issues affecting the latest version of the project will be reviewed and addressed as appropriate.

| Version        | Supported |
| -------------- | --------- |
| Latest         | ✅         |
| Older versions | ❌         |

---

## Reporting a Security Vulnerability

If you discover a security vulnerability in AppSec Sentinel itself, please report it responsibly.

Do **not** publicly disclose sensitive vulnerability details before the issue has been reviewed.

When reporting a vulnerability, please include:

* A clear description of the issue
* The affected component or file
* Steps to reproduce the issue where appropriate
* Potential security impact
* Any suggested remediation

Please avoid including unnecessary sensitive information.

---

## Scope

This security policy applies to vulnerabilities affecting:

* AppSec Sentinel repository content
* Project workflows
* Project automation
* GitHub Actions associated with this repository
* Future code or integrations maintained by the project

This policy does **not** apply to vulnerabilities discovered in third-party applications tested using AppSec Sentinel.

Those vulnerabilities should be reported to the appropriate application owner or vendor.

---

## Responsible Disclosure

Please:

1. Report the issue privately where possible.
2. Provide sufficient information for validation.
3. Allow reasonable time for investigation and remediation.
4. Avoid accessing data beyond what is necessary to demonstrate the issue.
5. Do not publicly disclose sensitive details before remediation.

---

## What to Expect

After receiving a security report, the project maintainer will aim to:

1. Review the report.
2. Validate the issue.
3. Assess security impact.
4. Determine appropriate remediation.
5. Communicate relevant updates where possible.

---

## Important Note

AppSec Sentinel is a security testing methodology and documentation project.

Users remain responsible for ensuring that all security testing performed using the project is authorized and complies with applicable laws, contracts, and organizational policies.
