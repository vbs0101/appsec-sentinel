# Contributing to AppSec Sentinel

Thank you for your interest in contributing to AppSec Sentinel! 🛡️

AppSec Sentinel aims to provide structured, practical, and responsible guidance
for authorized application security testing.

Contributions that improve testing methodology, accuracy, documentation, and
usability are welcome.

---

## Ways to Contribute

You can contribute by:

* Improving OWASP testing guidance
* Adding security testing modules
* Improving checklists
* Adding new workflows
* Improving reporting templates
* Adding realistic examples
* Fixing documentation
* Reporting bugs or inconsistencies

---

## Before You Start

Before making significant changes:

1. Check existing issues and discussions.
2. Clearly define the problem being solved.
3. Keep contributions focused and scoped.
4. Ensure content supports authorized security testing.

---

## Contribution Guidelines

### Keep Content Structured

Follow the existing project structure:

```text
modules/
checklists/
workflows/
templates/
examples/
docs/
```

Place new content in the appropriate directory.

---

### Keep Guidance Practical

Security guidance should be:

* Clear
* Structured
* Evidence-based
* Practical
* Actionable

Avoid vague recommendations.

---

### Validate Security Content

Do not present assumptions or theoretical issues as confirmed vulnerabilities.

Where appropriate, guidance should emphasize:

* Scope validation
* Reproducibility
* Evidence collection
* Realistic impact
* Finding validation

---

### Responsible Security Testing

All contributions must support legitimate and authorized security testing.

Do not add content intended to facilitate:

* Unauthorized access
* Destructive attacks
* Denial-of-service attacks against unauthorized targets
* Theft of credentials or sensitive information

---

## Adding a New Module

When adding a new security testing module:

1. Create the module in the appropriate `modules/` directory.
2. Clearly define its purpose.
3. Describe the relevant testing methodology.
4. Include validation guidance.
5. Include remediation guidance where appropriate.
6. Update relevant documentation.

---

## Adding a Checklist

Checklists should:

* Be easy to follow
* Track testing coverage
* Clearly distinguish tested and untested areas
* Avoid implying complete security coverage

---

## Documentation Style

Please use:

* Markdown
* Clear headings
* Short paragraphs
* Bullet points where appropriate
* Consistent terminology

Keep documentation professional and easy to understand.

---

## Pull Requests

Before submitting a pull request:

* [ ] Review your changes
* [ ] Check Markdown formatting
* [ ] Ensure file names are consistent
* [ ] Ensure internal references are correct
* [ ] Avoid unrelated changes
* [ ] Confirm the contribution supports authorized testing

Provide a clear pull request description explaining:

* What changed
* Why it changed
* Any important limitations

---

## Reporting Problems

If you find:

* Incorrect security guidance
* Broken references
* Inconsistent methodology
* Documentation problems

Please open an issue with sufficient detail to reproduce or understand the problem.

For sensitive security vulnerabilities affecting AppSec Sentinel itself, please
follow the instructions in `SECURITY.md`.

---

## Code of Conduct

Be respectful and constructive.

Security discussions should focus on improving the quality, accuracy, and
responsible use of AppSec Sentinel.

Thank you for helping improve AppSec Sentinel! 🚀
